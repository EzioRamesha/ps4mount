# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

PS4Mount is a PS5 homebrew payload (C, GPL-3.0-or-later) that lets a jailbroken PS5 play PS4 fake
PKGs straight from a USB drive without installing them. It is a single daemon (`build/ps4mount.elf`)
sent to an ELF loader on the console. There is no package manager, Makefile, or linter — just
`build.sh`, `test/run.sh`, and the GitHub Actions workflow.

## Commands

```sh
./build.sh          # builds build/ps4mount.elf (needs the PS5 Payload SDK, see below)
bash test/run.sh    # builds and runs all unit tests on the host — no console or SDK needed
```

- The build needs the [PS5 Payload SDK](https://github.com/ps5-payload-dev/sdk) in
  `/opt/ps5-payload-sdk` or at `$PS5_PAYLOAD_SDK`, plus `xxd` and bash. CI pins the SDK release in
  `SDK_VERSION` in `.github/workflows/build.yml`.
- `test/run.sh` compiles two host binaries with `${CC:-cc}` and runs them: `build/test/unit`
  (crypto, install-file builders, catalog, policy, pkg parser, …) and `build/test/web_unit`
  (the panel HTTP server, on port 18770). It then runs `node test/i18n_check.js` (skipped without
  node). To re-run one suite after `test/run.sh` has built it, execute the binary directly, e.g.
  `build/test/unit`. There is no per-test filter; tests are `CHECK(...)` assertions that print
  `FAIL file:line` and the binary exits non-zero.
- `build.sh` compiles `third_party/sqlite/sqlite3.c` only when `build/sqlite3.o` is missing —
  delete that file if you change the SQLite flags.

## Architecture

The daemon is split along one seam: **`src/main.c` is the only console-only code**; almost every
other module avoids PS5 syscalls so it can be compiled and tested on the host (macOS/Linux) by
`test/run.sh`.

- `src/main.c` (~3700 lines) — the daemon: the scan loop over `/mnt/usbN` / `/mnt/extN`, nullfs
  mounts, title registration (`sceAppInstUtilAppInstallAll`), klog following (game start / delete
  events, database-corruption reports), settings, notifications, and the `app_*` functions.
  `#define VERSION "PS4Mount X.Y.Z"` lives here.
- `src/web.h` is the seam between the panel and the daemon: `web.c` serves HTTP and calls the
  `app_*` interface declared there, which `main.c` implements (`test/web_unit.c` stubs them).
- `src/catalog.[ch]` — finds every `.pkg` on a drive, reads headers once (cached in
  `/data/ps4mount/catalog-<drive>.txt`), and groups each game with its update and add-ons;
  `catalog_link` resolves updates/add-ons across drives. Every pkg gets a `CAT_ROLE_*`.
- `src/policy.[ch]` — pure decision logic (add/keep/skip a game, panel state, low-space and
  speed verdicts) plus the `kv_*` helpers for the tab-separated state files in `/data/ps4mount/`.
  Deliberately has no system calls; put new decision rules here so they get host tests.
- `src/fm.[ch]` — path and name rules for the panel's file manager (drive-of, path and name
  validity, folder-covers-path), also system-call-free so it gets host tests.
- `src/build.[ch]` — generates the files a real install would leave (app/patch metadata, PlayGo
  records from the `tools/pdb_*_template.bin` layouts, the decrypted fake license).
- `src/pkg.[ch]` + `src/crypto.[ch]` + `src/keys.h` — PKG reading and fake-key entry decryption
  (keys regenerated by `tools/gen_keys.py` from LibOrbisPkg).
- `src/db.[ch]` — writes the library rows to the system `app.db`/`appinfo.db` via the vendored
  SQLite amalgamation in `third_party/sqlite/`.
- `src/safety.c`, `src/speed.c`, `src/origin.c`, `src/logfile.c` — corruption-pause and retry
  limits, drive read-speed tests, move-back records, log rotation.

### Embedded assets

The web panel UI is **one file, `web/index.html`**, embedded into the binary at build time via
`xxd` (`build/page_data.h`), like the icon and the PlayGo templates. Editing the panel means
editing that HTML/JS file and rebuilding. Panel translations live in the `I18N` object inside it
(English, Spanish, Portuguese (Brazil), French); `test/i18n_check.js` fails if any language is
missing a text or its `{value}` placeholders differ — adding a panel string means adding it to
every language.

### On-console layout (useful when reading the code)

State, settings, and the log live under `/data/ps4mount/`. Generated install files and symlinks to
the pkgs live under `/system_data/ps4mount/` (`HOLD_DIR`), mounted over `/user/app/<TITLE_ID>`
with nullfs — the console's delete can only remove links, never the `.pkg` on the drive.

## Releases

1. Bump `#define VERSION "PS4Mount X.Y.Z"` in `src/main.c` and commit.
2. Tag `vX.Y.Z` and push the tag. CI refuses a tag that does not match `VERSION`, runs the tests,
   builds, and publishes the release (a `-` in the tag marks it a prerelease).

## Conventions

- Every source file starts with the `SPDX-License-Identifier: GPL-3.0-or-later` header.
- Comments and user-facing text (README, panel, notifications) are written in plain, simple
  English sentences — match that style. Console-sent messages (log, notifications) stay in
  English; only the panel is translated.
- Credits in the README note where code or data came from; PKG internals reference LibOrbisPkg.
  Do not copy code from other projects without updating the Credits and License sections.
